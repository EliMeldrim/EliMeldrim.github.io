About

Library Checkout System is a deliberately classic server-rendered app — no SPA, no client framework — managing a small library's catalog, members, and circulation across four media types (books, DVDs, audiobooks, magazines). The dashboard shows at-a-glance counts and a merged checkout/return activity feed; the catalog is searchable and filterable with live availability computed as copies owned minus active loans; item and member detail pages carry full loan history; and an overdue report lists every unreturned loan past its due date with days overdue, sortable four ways, with overdue rows highlighted throughout the app. Returns can be recorded from any of the four places you'd naturally be standing when a book comes back.

The circulation rules are the substance: no checkout when all copies are out, only Active members may borrow, and a member can't have duplicate checkouts of the same item — all enforced server-side in a CirculationService behind an interface, keeping the Razor Page models thin. Dates go through .NET's TimeProvider abstraction instead of DateTime.Now, which makes overdue logic testable, and enums are stored as strings so the SQLite database stays human-readable. On first run the database creates and seeds itself with 25 items, 8 members, loan history, and several overdue loans dated relative to “today” — so the demo always has overdue rows to show.

A 16-test xUnit suite exercises the checkout/return/overdue rules against EF Core running on an in-memory SQLite connection — the same provider as production, so relational behavior actually matches — with a frozen TimeProvider for deterministic date assertions.
